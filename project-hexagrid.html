Hexagrid: VLM-Guided Precision Landing

Autonomous landing-site selection with a vision-language model in the decision loop. The drone captures six candidate views, a single VLM call chooses the safest, and a confidence loop then locks onto one cell of a grid overlaid on the winner before descent. Runs against PX4 SITL in AirSim with a local VLM — no cloud inference.

Code

How it works

Phase 1 — snap selection in one inference

The six candidate snaps are composited into a single labelled 3×2 mosaic and sent to the VLM as one image, which returns the number of the safest landing zone.

Comparison is the actual task. Scoring six images independently costs six inferences and still leaves the model unable to see the alternatives it is ranking against. A mosaic makes the comparison native to the prompt, and costs one call.

Phase 2 — grid confidence lock

A numbered 4×4 grid is overlaid on the winning snap and repeatedly re-queried. Cell scores are decayed and boosted across rounds until one crosses a lock threshold.

This is the part that matters for safety. A single VLM answer is not trustworthy enough to commit an aircraft to a landing; requiring a cell to win repeatedly turns an unreliable one-shot judgement into a stable decision, and a hallucinated answer that does not recur simply decays away.

Phase 3 — world alignment

The locked grid cell is converted into a metric offset in the world frame using camera intrinsics and vehicle attitude, so the flight controller receives a position target rather than a pixel.

Operator interface

Every phase pushes its current overlay and a status line into the QGroundControl video feed. The operator watches the reasoning as it happens — which view was chosen, which cell is winning — rather than a raw camera stream. An autonomous system that cannot be watched cannot be trusted, and the overlay costs almost nothing to produce.

Notes

The camera that pointed the wrong way

An AirSim settings.json with "Pitch": 0 produces a forward-facing "down" camera — which I confirmed by seeing the horizon and the vehicle's own rotors in frame. The fix is pitch −90 plus a stabilised gimbal block, so the image stays truly nadir at any airspeed and body tilt. Worth stating plainly because it silently invalidates every geometric assumption downstream.

Composes with Survey-RAG

The pipeline hands off from the Survey-RAG arrival hold, making search and landing a single flow: retrieve a target from language, fly to it, then choose a safe touchdown point on arrival.

Related: ViT grid-forwarding study

A companion study comparing five strategies for extracting region features from a vision transformer — full forward pass, attention masking, crop-and-forward, sliding window, and multi-scale — measured on aerial imagery for compute cost, retained spatial context and interpretability. The sliding-window approach gave the best balance for landing-zone analysis: 36 patches instead of 1600, with surrounding context preserved.
